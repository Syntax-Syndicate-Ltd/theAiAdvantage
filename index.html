What is Gen AI?

A fundamental paradigm shift from classification to creation.

Traditional AI

Focuses on pattern recognition, classification, and predicting labels based on existing rules or data boundaries.

Example: Spam filter labeling an incoming email as "Spam" or "Inboxed".

Generative AI

Learns underlying mathematical patterns to synthesize entirely new, creative artifacts matching the training domain.

Example: ChatGPT writing a custom email newsletter from a 3-word prompt.

How GenAI Works: The Core Loop

From raw unstructured web data to predictive probability engines.

1. Massive Datasets

Models ingest billions of public web pages, books, codes, and images to learn human language structure.

2. Pattern Learning

Instead of memorizing facts, models analyze mathematical weights and neural patterns mapping words to meanings.

3. Token Prediction

Generates final outputs step-by-step by constantly calculating the statistical probability of "what comes next".

💡 Everyday Analogy: Smart Auto-Complete. Think of your phone's predictive keyboard guessing the next word as you type. Generative AI works on the exact same probability math—it just reviews the entire internet's context to predict pages of text, code, or images!

What is an LLM & Types of LLMs

Understanding the technology behind large language models and their core operational divisions.

What is an LLM?

A Large Language Model (LLM) is a deep learning system trained on billions of parameters. At its core, it is a supercharged prediction engine designed to guess the most statistically likely next word in a sequence.

Inference Probability Loop
Prompt: "The sun rises in the..."
"east" 99.4% (Highest Probability)
"morning" 0.4%
"sky" 0.2%

Proprietary Models (Closed-Source)

Natively hosted by providers, accessed via secure cloud APIs. Highly optimized for massive reasoning workloads (e.g., GPT-4o, Claude 3.5 Sonnet, Gemini 1.5 Pro).

Open-Weights Models (Local / Open-Source)

Weights are downloadable and hostable on custom servers or local corporate GPUs, ensuring 100% data privacy and customization (e.g., Llama 3.1, Mistral, Gemma 2).

Domain-Specific (Fine-Tuned) Models

Foundation models specifically re-trained on narrow professional dataset corpora (medical, coding, financial, law) to handle specialized tasks with precision.

🧩 What is a Token?

Word fragments or syllables. Models don't read words whole; they segment them into standard dictionary pieces to understand patterns.

📏 Rule of Thumb

1 Token ≈ 4 characters or 0.75 English words. 100 tokens is roughly 75 English words.

🌐 Vocabulary Index

Each token corresponds to a unique number in the model's vocabulary list (usually containing 50,000 to 100,000+ entries).

Intro to LLMs: Next-Token Prediction

Models generate sentences step-by-step by calculating probability scores for the next token.

Active Token Context

The sky is clear and blue

Once the tokenizer converts text to IDs, the model reviews the entire context sequence to predict the single highest-probability next token.

Next-Token Candidate List

"blue" 92.4% Probability
"gray" 3.8%
"cloudy" 1.5%
"bright" 0.9%

🔄 Autoregressive Loop

Models generate text one token at a time. Once a token is selected, it is appended to the prompt, and the model runs again to predict the next token.

🎲 Probability Score Rankings

The model outputs mathematical weights for every token in its dictionary. The highest scores represent the most logical sentence completions.

🌡️ Temperature Controls

Slide controllers that adjust prediction randomness. Lower temperature = predictable Copywriter; higher temperature = creative Storyteller.

LLM Architecture: The Transformer

The groundbreaking deep learning architecture introduced in 2017.

Key Processing Layers

1. Input Embedding Layer

Ingests raw text and projects tokens into multi-dimensional numerical coordinate vectors.

2. Transformer Blocks (Self-Attention)

Processes relations between all words simultaneously, extracting contextual and reasoning pathways.

3. Output Layer

Converts mathematical vectors back into human-readable text tokens.

💡 Technical Breakthrough: By processing entire sentences simultaneously (instead of word-by-word like older RNN networks), the Transformer unlocked massive computing parallelization, directly enabling today's internet-scale GenAI revolution.

LLM Architecture: Attention Mechanism

Attention allows models to dynamically weigh relationships between words regardless of distance.

Resolving Contextual Ambiguity

The cat sat on the mat because it was tired.

Self-attention maps mathematical correlation values between "it" and "cat". Unlike traditional engines that read word-by-word sequentially, self-attention links semantic relationships globally across the entire sequence.

Attention Score Distribution

😺 cat 85% (Strong Connection)
💤 tired 12%
🏠 mat 2%
🌐 others 1%

💡 The model learns that "it" stands for the "cat" because of context clues like "tired".

💡 The Highlighter Analogy: When humans read "The trophy didn't fit in the suitcase because it was too big," we instantly associate "it" with the trophy. Attention mathematically "highlights" related words so the model doesn't lose track of pronouns in long sentences.

Prompting: What & Why

A prompt is the instruction input. Better engineering directs higher fidelity output.

Vague Prompt Input

"Write about dogs."
Weak Output Result

"Dogs are domesticated mammals. They are canines and have been human companions for centuries..."

Engineered Prompt Input

"Write a 100-word engaging Instagram post about rescue dogs. Use 3 emojis and include a clear call-to-action for local shelters."
Strong Optimized Output

"🐶 Looking for a new best friend? Rescue dogs fill our lives with pure joy. Adoption saves lives! Check out your local shelter today to meet your match. ❤️ #AdoptDontShop"

Core Prompting Techniques

Proven frameworks to improve logical accuracy and output formatting.

Zero-Shot

Directly asking the model to complete a task without feeding any input-output examples beforehand.

"Translate 'hello' to French."

Few-Shot

Providing 2-3 explicit example structures first to format the style before asking the target query.

"Apple -> Fruit | Carrot -> Veg | Broccoli -> ___"

Chain-of-Thought

Instructing the model to "think step-by-step" to break down mathematical and logical steps sequentially.

"Let's trace this logic step-by-step: 1. ..."

How to Write the Perfect Prompt

A general formula to guide LLMs toward high-fidelity, deterministic outputs in four steps.

1

Assign a Persona

Define "who" the AI is. Setting a role anchors the vocabulary and expertise range.

"Act as a senior DevOps engineer auditing a database cluster..."
2

Provide Context

Explain the "what" and "why". Give background details, target audience, and raw data.

"We recently migrated our user registry to PostgreSQL and noticed latency peaks..."
3

Set Constraints

Establish boundaries. Specify what to avoid, length constraints, or styling rules.

"Do not modify the table index schema. Keep the audit report under 250 words..."
4

Format Output

Dictate the response schema. Request JSON blocks, Markdown, lists, or spreadsheets.

"Output as a markdown table with 'Query Type', 'Latency', and 'Action' columns."

The Agentic Loop: Self-Correction & Reflection

Beyond single-shot prompts: how agents review, correct, and refine their own outputs recursively.

1. Execution

Agent attempts the task, generating code, plans, or documents based on raw prompts.

2. Evaluation

Outputs are validated against constraints (e.g., test compilers, schema parsers).

3. Reflection

The model analyzes any compile failures, error stack logs, or missing requirements.

4. Refinement

Agent updates its weights/prompt context and runs again, looping until standard criteria is met.

🔄 Loop back with reflection log (Iterate until specific requirements are met)

🔄 Why This Matters: LLMs are prone to one-shot errors. By wrapping them in a **reflection cycle**—where the output is compiled, verified for errors, and re-fed as context—agents can self-correct their own bugs and work autonomously until the objective is reached.

The Knowledge Cutoff & Hallucination Problem

Why static model weights require real-time information retrieval bridges.

Fixed Parametric Memory

Models only know what they read in their training data prior to training. They are completely blind to current news, private company files, or API updates.

⚠️ Risk: High chances of "Hallucinating" plausible-sounding lies.

Active Semantic Retrieval

Searching dynamic external databases (documents, web APIs) and feeding relevant text snippets directly into the prompt before generating.

✅ Result: Truth-grounded answers citing verifiable reference sources.

What is RAG? (The Core Concept)

Giving the LLM an "open-book exam" using your own documents.

1. User Question

Employee asks: "What is our company policy on parental leave?"

2. Document Retrieval

System queries company HR storage and pulls actual policy paragraphs matching the topic.

3. Grounded Answer

The LLM reads retrieved rules as references and drafts a precise factual summary answer.

Closed-Book Exam (Traditional LLM): The student tries to answer questions relying only on memory from classes attended months ago. They might guess or misremember (hallucinate).

Open-Book Exam (RAG System): We search the library, find the exact page of the textbook containing the answer, place it in front of the student, and ask them to summarize it.

How Agents Work: The Autonomy Loop

The continuous cognitive cycle of modern agentic systems.

Cognitive Loop Plan - Act - Reflect

1. Perceive

Reads user goal, evaluates environment parameters and API keys.

2. Plan

Decomposes the primary objective into small, sequential step tasks.

3. Act

Executes searches, edits files, calls APIs, or writes code scripts.

4. Reflect

Audits output success. If errors occur, re-plans and starts loop again.

💡 Everyday Analogy: A Chef in a Kitchen. Instead of just listing lasagna ingredients (passive chatbot), the chef reads the order (perceive), outlines recipe steps (plan), chops vegetables and boils pasta (act), tastes the sauce to adjust seasoning (reflect), and serves only when perfect!

The Hidden Dangers of "Vibe Coding"

What happens when we delegate software scaling, cost budgets, and security entirely to vibes.

1. Scaling & Performance Bottlenecks

AI builders write queries that work for single-user dev but crash under load. Redundant database scans, lack of caching, and unpaginated tables trigger server timeouts under real traffic.

2. Runaway API Cost Loops

Uncontrolled recursive agentic loops or lack of request throttling can trigger thousands of repeated API calls, resulting in sudden, massive service provider bills overnight.

3. Exposed Security Vulnerabilities

Generative tools regularly expose sensitive credentials, leave open CORS endpoints, bypass encryption, or hardcode credentials directly in Git commits.

Risks & Limitations of Agentic AI

Why autonomous code execution requires robust human checkpoints.

Critical Agent Risks

If left unmonitored, autonomous loops can enter infinite recursion cycles, execute unwanted database deletions, or accumulate massive API bills.

⚠️ Caution: Never grant write-access to financial or core server APIs.

Human-In-The-Loop

Define strict sandboxes, implement spending ceilings, use read-only APIs, and mandate manual confirmations before destructive actions.

🛡️ Best Practice: Trust, but continuously monitor system logs.
